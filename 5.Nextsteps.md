## Part 5: Next Steps and Implementation Plan

### Phase 1: Formalization

**Goals:**

- Formalize all concepts with precise mathematical definitions
- Write formal proofs where possible
- Identify limits of framework

**Deliverables:**

1. **Formal definition of compound QDs** with coupling typology
2. **Operational definition of concept-fidelity** (or proxy metrics)
3. **Algorithms for:**
    - QD extraction with coupling detection
    - Equivalence class construction
    - Total ordering via concept-fidelity
    - Betweenness evaluation
    - Non-necessary QD filtering
    - Error propagation tracking
4. **Formal statement of assumptions and their testability**

### Phase 2: Implementation

**Goals:**

- Build working prototype system
- Test on small dataset

**System Components:**

```
1. QD Extractor
   - Input: Corpus of student answers
   - Output: Refined QD set (with compound QDs)
   - Methods: Iterative LLM prompting, coupling detection

2. Equivalence Class Builder
   - Input: QD set, annotated corpus
   - Output: Lattice of equivalence classes
   - Methods: QD presence detection, graph construction

3. Concept-Fidelity Ranker
   - Input: Texts within equivalence class
   - Output: Total ordering
   - Methods: Iterative extraction, pairwise comparison

4. Betweenness Grader
   - Input: New text, reference texts, equivalence class
   - Output: Grade + position + feedback
   - Methods: Betweenness evaluation, comparison

5. Adversarial Filter
   - Input: Raw text
   - Output: Cleaned text (adversarial content removed)
   - Methods: Pattern matching, statistical detection

```

### Phase 3: Data Collection

**Goals:**

- Collect large, diverse dataset
- Ensure high-quality annotations

**Datasets to Collect:**

**Physics (200 answers):**

- "What is voltage?"
- "Explain Newton's second law"

**Computer Science (200 answers):**

- "What is recursion?"
- "Explain polymorphism"

**Math (200 answers):**

- "What is a derivative?"
- "Explain proof by induction"

**For each answer:**

- Student response (anonymized)
- Instructor grade (0-100)
- Instructor notes on errors/strengths
- Domain expert grade (for validation)

**Adversarial subset (100 answers):**

- Clean answers + adversarial manipulations
- Multiple attack types (flattery, injection, magic words)

### Phase 4: Validation

**Goals:**

- Test all research hypotheses (RQ1-RQ8)
- Compare to baselines
- Measure all metrics

**Experiments:**

**RQ1: Orthogonality Detection**

- Run on all 600 answers
- Compute MI for all QD pairs
- Classify coupling strength
- Correlation with instructor ratings

**RQ2: Compound QD Impact**

- Compare accuracy: atomic vs. compound vs. LLM-guided
- Measure interpretability

**RQ3: Structure vs. Correctness**

- Correlations analysis
- Error rate at 100% structural completeness

**RQ4: Concept-Fidelity Validation**

- PhysICO-style transfer tasks
- Correlation with deep understanding

**RQ5: Betweenness Robustness**

- Faithfulness with different QD structures
- Instructor comprehension ratings

**RQ6: Adversarial Defense**

- Attack success rates
- Accuracy on clean texts

**RQ7: Error Propagation**

- Compare grading schemes
- Instructor fairness ratings

**RQ8: Consistency vs. Correctness**

- 2D plot across LLMs and prompts
- Identify orthogonality empirically

**Baselines to Compare:**

1. **Zero-shot GPT-4** (no structure)
2. **Few-shot with rubric** (traditional prompting)
3. **MT-Bench style** (pairwise comparison)
4. **G-Eval** (CoT evaluation)
5. **Prometheus** (fine-tuned evaluator)

**Metrics:**

- **Accuracy:** Spearman ρ with instructor grades
- **Consistency:** Cohen's κ across trials
- **Adversarial robustness:** Attack success rate
- **Interpretability:** Instructor ratings (5-point scale)
- **Efficiency:** Time per assessment, API costs

### Phase 5: Refinement

**Goals:**

- Iterate based on validation results
- Fix issues discovered in testing
- Optimize for performance

**Expected Issues and Fixes:**

**If orthogonality violations are severe:**

- Implement compound QD merger automatically
- Test fuzzy QD presence (degree of structure)

**If concept-fidelity is inconsistent:**

- Try different prompting strategies
- Use ensemble of LLM judgments
- Calibrate with validated examples

**If betweenness fails with coupling:**

- Require compound QDs before betweenness
- Use projection more aggressively

**If adversarial defense has false positives:**

- Refine detection patterns
- Use whitelist of legitimate phrases

**If error propagation tracking is inaccurate:**

- Improve dependency graph construction
- Use LLM to identify foundational vs. derived claims
