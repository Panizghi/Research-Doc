Section 4: QD Refinement Operators (EXPANDED)

4.1 Overview of Refinement Operators

Purpose: Iteratively improve Quality Dimension sets to better capture corpus variation and pedagogical intent.

Four Core Operators:

MERGE - Combine coupled dimensions SPLIT - Decompose overly broad dimensions ADD - Introduce missing dimensions DROP - Remove non-discriminating dimensions

Key Principle: Operators are applied based on corpus analysis, not instructor intuition alone.

Betweenness Notation:

A = Top/best reference answer D = Failure/unacceptable reference answer B(A, x, D) = x is between A and D Position descriptors: "closer to A" (upper range), "middle", "closer to D" (lower range)

4.2 MERGE Operator

Definition

MERGE(D₁, D₂, ..., Dₖ) → D_compound

Combines multiple atomic dimensions that are irreducibly coupled into a single compound dimension.

When to Apply (Detection Criteria)

Statistical Co-occurrence:

If dimensions D₁, D₂ appear together in >85% of correct answers AND rarely appear independently (<5% each) → Consider merging

Mutual Information:

If I(D₁, D₂) > threshold (e.g., 0.7) → Strong coupling detected

Pedagogical Coupling:

Concept cannot be meaningfully explained with only one dimension Separation creates false impression of independent concepts

Terminology

Atomic dimensions: Original, fine-grained QDs before merging Compound dimension: Merged QD containing multiple atomic components Coupling strength: Measure of co-occurrence (MI, correlation, frequency) Irreducible coupling: Cannot separate without losing meaning

4.3 SPLIT Operator

Definition

SPLIT(D_broad) → {D₁, D₂, ..., Dₖ}

Decomposes overly broad dimension into finer-grained dimensions that capture distinct aspects.

When to Apply (Detection Criteria)

High Internal Variation:

If texts with D_broad=1 show widely varying concept-fidelity AND variation corresponds to distinct sub-concepts → Consider splitting

Multiple Independent Aspects:

Dimension conflates separate pedagogical goals Some texts have one aspect but not another Betweenness positioning becomes ambiguous

Equivalence Class Confusion:

If texts in same equivalence class based on D_broad have vastly different quality → D_broad isn't capturing meaningful distinction

Terminology

Over-broad dimension: QD that encompasses multiple separable concepts Atomic sub-dimensions: Finer-grained QDs resulting from split Orthogonal aspects: Sub-dimensions that can vary independently Discriminative power: Ability to distinguish quality differences

4.4 ADD Operator

Definition

ADD(D_new) → QD_set ∪ {D_new}

Introduces a new dimension that captures variation present in corpus but not covered by existing QDs.

When to Apply (Detection Criteria)

Unexplained Variance:

If texts with identical QD profiles have significantly different concept-fidelity → Missing dimension likely exists

Iteration Feedback:

LLM critique suggests: "Missing aspect: [concept]" AND concept appears in multiple corpus texts → Add new dimension

Instructor Observation:

Pedagogically important aspect not captured by current QD set AND aspect varies across student responses → Add dimension

Terminology

Coverage gap: Aspect of understanding not captured by current QDs Discriminative dimension: New QD that helps distinguish quality levels Emergent pattern: Previously unnoticed commonality in corpus

4.5 DROP Operator

Definition

DROP(D_non_discriminating) → QD_set \ {D_non_discriminating}

Removes a dimension that fails to capture meaningful variation in the corpus.

When to Apply (Detection Criteria)

Universal Presence:

If dimension present in >95% of texts (correct and incorrect) → Doesn't distinguish quality → Drop it

Universal Absence:

If dimension present in <5% of texts → Not pedagogically relevant to this question → Drop it

No Correlation with Quality:

If texts with D=1 have same average concept-fidelity as texts with D=0 → Dimension doesn't predict quality → Drop it

Redundancy:

If dimension always co-occurs with another dimension (perfect correlation) → Redundant (consider merging instead if both matter) → Drop one

Terminology

Non-discriminating dimension: QD that doesn't help distinguish quality levels Saturated dimension: Present in (nearly) all texts Rare dimension: Present in very few texts Redundant dimension: Perfectly correlated with another QD

4.6 Summary: When to Use Each Operator
MERGE: - Trigger: High co-occurrence (>85%) + high mutual information (>0.7) - Goal: Combine irreducibly coupled dimensions - Example: energy + charge + ratio → "energy-per-charge relationship" - Benefit: Prevents false positives from dimension checklist

SPLIT: - Trigger: High internal variance in concept-fidelity within same QD profile - Goal: Separate conflated concepts into distinct dimensions - Example: "explains pointers" → address_concept + operators + use_cases + syntax - Benefit: Distinguishes mechanism understanding from application knowledge

ADD: - Trigger: Unexplained variance in concept-fidelity + LLM suggests missing aspect - Goal: Capture pedagogically important variation not in current QD set - Example: virtual_functions: add vtable_implementation + applications - Benefit: More precise betweenness positioning based on knowledge profile

DROP: - Trigger: Saturation (>95% or <5%) OR no correlation with quality - Goal: Remove non-discriminating dimensions - Example: "mentions_tree" (98% presence), "written_in_english" (100%) - Benefit: Cleaner equivalence classes, fewer irrelevant distinctions

4.7 Iterative Refinement Algorithm
Complete Process:

ITERATION 1:

Start with seed QDs (instructor-provided or LLM-generated) LLM analyzes corpus with current QDs Produce QD profiles for all texts

ITERATION 2: 4. LLM critiques QD set:

Detect coupling → suggest MERGE Detect conflation → suggest SPLIT Detect gaps → suggest ADD Detect saturation/irrelevance → suggest DROP

Apply operators to refine QD set

ITERATION 3: 6. Re-analyze corpus with refined QDs 7. Check stopping criteria:

Equivalence classes stable? Concept-fidelity variance explained? Pedagogical coverage adequate?

If not satisfied → return to step 4 If satisfied → DONE

TYPICAL: 2-3 iterations sufficient
